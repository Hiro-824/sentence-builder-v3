# Syntablo セクション4 挿入図

`index.html` を開くと、4点の図・編集用HTML・撮影原本・切り抜きを一覧できます。

## 保存内容

- `originals/01-*.png` 〜 `10-*.png`：未加工の画面全体。3600 × 2200 px。
- `originals/probe.png`：撮影準備時のゲスト画面。参考用。
- `crops/`：対応する原本のブロック領域を切り抜いた画像。注釈なし。
- `figures/figure-*.png`：本文への挿入用。幅2400 px。
- `figures/figure-*.html`：画像を埋め込んだ注釈付き図。単独で開ける編集用HTML。
- `manifest.json`：ヘッドレス設定、撮影範囲、要素座標、各状態の文法判定。
- `scripts/`：撮影・合成の再現用スクリプト。

## 撮影・加工方法

Playwright の Chromium を `headless: true` で起動し、ローカル開発サーバーの `/app/sandbox` をゲスト利用した。viewport は1800 × 1100 CSS px、deviceScaleFactor は2。

例の配置は、実際のアプリ内の Renderer に既存の語彙ブロックを読み込んで行った。ブロックの新作やスクリーンショット中の文字の置換はしていない。apple は自由練習の一覧にはないため、既存の `src/data/lesson-blocks.ts` が提供する `lesson_noun_apple` を読み込んだ。

接続はアプリの previewInsertion / previewAttachment でプレビューし、実際の文法エンジンの validate が成功した場合のみ insertBlock / attachBlock を実行した。受動態用語形への変更は実際の選択メニューのイベントで実行した。画面表示、訳、GAP解決表示はいずれも既存の描画処理による。

元画像を撮影した直後に、同じ画面から clip を指定したスクリーンショットを保存した。切り抜きの画像内容は変更せず、HTMLで見出し・注記・矢印・破線を追加し、再度ヘッドレスChromiumでPNGに出力した。AIによるブロックの描き直しは行っていない。

キャプチャは状態の例示であり、すべての接続操作をポインターのドラッグによって行った録画ではない。

## 再出力

リポジトリ直下で、ローカル開発サーバーをポート3100で起動した上で実行する。

```sh
node artifacts/section4-figures/scripts/capture.cjs
node artifacts/section4-figures/scripts/compose.cjs
```

Playwright はこの環境に既存のnpmキャッシュにあるものを使用している。他環境ではスクリプト冒頭のPlaywrightの読み込み先を変更する。
